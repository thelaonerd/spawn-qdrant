# spawn-qdrant

Linux（またはPodman）でDockerを使用して、複数のQdrantインスタンスを簡単に起動、管理、およびクリーンアップするためのGoで記述されたCLIユーティリティ。

## 機能

- **複数インスタンス管理**: 自動インクリメントされたポートを持つ、複数の隔離されたQdrantインスタンスを起動。
- **スマートリソースチェック**: 利用可能なRAMに基づいて、システムが処理できるインスタンス数を自動的に推定。
- **自動ネットワーク**: すべてのインスタンスを専用の`qdrant_network`に接続。
- **安全なクリーンアップ**: `clean`コマンドはインスタンスを停止し、データを`~/qdrant_backup`にバックアップし、ストレージディレクトリを安全に削除。
- **ランタイム非依存**: `docker`または`podman`を自動的に検出して使用。

## 前提条件

- **OS**: Linux
- **ランタイム**: DockerまたはPodmanがインストールされ、実行されていること。
- **言語**: Go 1.25+ (ソースからビルドする場合)。

## インストール

1. リポジトリをクローン:
   ```bash
   git clone https://github.com/thelaonerd/spawn-qdrant.git
   cd spawn-qdrant
   ```

2. バイナリをビルド:
   ```bash
   go build -o spawn-qdrant main.go
   ```

3. (オプション) PATHに追加:
   ```bash
   sudo mv spawn-qdrant /usr/local/bin/
   ```

## 設定

アプリケーションはデフォルトを使用しますが、以下の`.env`ファイルを使用して設定できます。
```env
# 最初のインスタンスの開始ポート
REST_PORT=6333
GRPC_PORT=6334
```
*後続のインスタンスはポートを2ずつ増やします (例: インスタンス 2: 6335/6336)。*

## 使用法

### 1. 容量の確認 (`check`)

`check`コマンドはシステムRAMを検証し、起動時 (256MB/インスタンス) および効率的な運用 (512MB/インスタンス) に使用できるインスタンスの数を報告します。
```bash
spawn-qdrant check
```
*出力例:*
```
Available RAM: 12236 MB
Max instances (startup only, 256MB/each): 47
Max efficient instances (vector ops, 512MB/each): 23
```

### 2. インスタンスの起動 (`spawn`)

**N個のインスタンスを起動:**
```bash
spawn-qdrant spawn 2
```
*これにより、`qdrant-01`と`qdrant-02`が起動されます。データは`~/.qdrant_storage01`と`~/.qdrant_storage02`に保存されます。*

`instance_count`が指定されていない場合、デフォルトで推定ロジックが使用されます (checkコマンドと同様)。

> **注**: このコマンドは、十分なRAMがあるかを確認します。起動制限を超えるとエラーが表示され、効率的制限を超えると警告が表示されます。

### 3. インスタンスの停止 (`stop`)

**特定のインスタンスを停止:**
```bash
spawn-qdrant stop 2
# qdrant-02を停止および削除
```

**すべてのインスタンスを停止:**
```bash
spawn-qdrant stop all
# すべてのqdrant-*コンテナとネットワークを停止および削除
```

### 3. クリーンアップ (`clean`)

破壊的なコマンドで、バックアップを保持しながら環境をリセットします。安全な動作を確保するための複数のセキュリティ対策が含まれています。
```bash
spawn-qdrant clean
```

**実行内容:**
1. すべてのQdrantインスタンスを停止します。
2. すべての`~/.qdrant_storage*`ディレクトリを`~/qdrant_backup/`に`tar.gz`形式でバックアップします。
3. 元の`~/.qdrant_storage*`ディレクトリを削除します。

**セキュリティ機能:**
- **シンボリックリンク検証**: 権限昇格を防ぐために、各ストレージパスが実際のディレクトリであり、シンボリックリンクではないことを確認します。
- **プロセスタイムアウト**: 自動タイムアウト (バックアップの場合は10m、クリーンアップの場合は5m) は、`sudo`がパスワードの入力を待つ必要がない環境 (例: CI/CD) でアプリケーションが無限にハングしないようにします。
- **インタラクティブチェック**: ターミナルからパスワードを読み取るのは、インタラクティブセッションが検出された場合にのみ試みます。
- **引数インジェクション保護**: 標準のコマンドライン区切り記号 (`--`) を使用して、悪意のあるパスがコマンド引数として解釈されないようにします。

> **注意**: このコマンドは`sudo`を使用してストレージディレクトリを削除します。これは、Dockerが作成したボリュームをrootが所有しているためです。パスワードの入力を求められる場合があります。

### 4. ロックファイルのメカニズム

このアプリケーションは、ポートまたはリソースの競合を防ぐために、`~/.spawn-qdrant.lock`という名前のロックファイルを、複数の同時`spawn`セッションで使用します。

- **ロックの作成**: `spawn`を実行すると自動的に作成されます。
- **ロックの削除**: `stop all`、`clean`、または最後のインスタンスを停止すると自動的に削除されます。
- **手動での削除**: アプリケーションがクラッシュし、ロックファイルが残った場合は、手動で削除できます。
  ```bash
  rm ~/.spawn-qdrant.lock
  ```

### 5. 再起動ポリシー

起動されたすべてのコンテナは `--restart unless-stopped`という設定で作成されます。これにより、ホストマシンが再起動した場合、またはDocker/Podmanサービスが再起動した場合に、これらのコンテナが自動的に再起動されます (例: `spawn-qdrant stop`で明示的に停止しない場合)。

### 6. 起動遅延

複数のインスタンスを起動する場合、ツールは各インスタンスの起動の間に30秒の遅延を設けます。これにより、前のインスタンスがリソースを初期化するのに十分な時間が確保されます。

## トラブルシューティング

- **"Insufficient RAM"**: ツールは、`n * 256MB > 利用可能なRAM`の場合、インスタンスの起動を防止します。インスタンスの数を減らしてください。
- **"Permission Denied during Clean"**: `sudo`権限があることを確認してください。これは、rootが所有するストレージフォルダを削除するために必要です。
- **"Lock file exists"**: 別のインスタンスが実行されている可能性があります。そうでない場合は、手動で`~/.spawn-qdrant.lock`を削除します。
- **"Docker/Podman not found"**: どちらか1つがインストールされ、システムPATHに追加されていることを確認してください。
